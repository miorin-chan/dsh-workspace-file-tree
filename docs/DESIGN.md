# 文件目录分组设计

## 分组语义

`workspace-file-tree` 是独立的工作区分组方式。
切换器的 `workspace-tree` 使用已经登记的工作区作为父节点，文件目录分组还将共享但未登记的分叉目录纳入树中。
例如，`/team/api` 和 `/team/web` 会归入 `team`，即使 `/team` 未登记。
没有分叉的未登记中间目录可折叠，同名工作区沿用切换器的路径区分。

注册工作区以工作区 ID 标识。每个 ID 在投影中出现一次，路径相同的工作区保留为同级节点，后代归属于首个登记项。
合成目录使用独立的键空间。Unix 路径保留大小写，Windows 路径的键合并大小写及分隔符差异，并隔离盘符与 UNC 共享根。
切换器将目录键用作节点标识，并从节点的展示路径获取搜索和悬停提示所需的文字。
父节点可展开或折叠。工作区节点继续承载自己的会话及原有操作。
合成节点只提供目录层级，只有已登记的工作区可以用于新会话选区。
工作区注册、会话成员、手动排序和归档仍由 DSH 浏览器负责。

## 接入切换器

插件等待工作区切换器提供 `workspaceSwitcherGrouping` Client 服务，然后注册稳定 ID、本地化名称与目录层级投影。
服务可用时注册，服务或插件卸载时释放。分组选项随注册状态更新。
切换器使用现有组件绘制节点，根据节点类型决定可用动作，并负责搜索、排序、菜单及分组记忆。

插件可独立启停。目录分组只作用于工作区切换器。

## 验收

- 验证共享未登记目录、已登记祖先、同名工作区、不同驱动器和 UNC 共享根的层级。
- 启停插件时，检查切换器分组选项同步增减。
  活动分组失效时验证切换器的回退行为。
- 验证原有的会话与工作区操作。新会话选区须允许展开目录、选择已登记工作区。
